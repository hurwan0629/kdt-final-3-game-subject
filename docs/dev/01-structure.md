# 코드 구조와 책임 분리

게임의 중심은 `GameCore`입니다. 사람이 플레이할 때는 `GameApplication`이 입력을 전달하고 `Renderer`가 상태를 그립니다. 강화학습할 때는 `TankEnv`가 같은 코어를 사용해 관찰값과 학습 보상을 만듭니다.

## 파일별 책임

| 파일 / 중심 객체                                 | 담당하는 일                                    | 변경 예시            |
| ------------------------------------------ | ----------------------------------------- | ---------------- |
| `config.py` / 설정 dataclass                 | 기본 수치, 지형 옵션, 관찰 크기, 학습 보상 계수             | 체력·적 수·재장전 시간 조절 |
| `main.py` / `GameApplication`              | 키·마우스 입력, 메뉴 상태, 시간 누적, 사람이 보는 게임 흐름      | 새 단축키·메뉴 동작 추가   |
| `game_core.py` / `GameCore`                | 이동, 발사, 충돌, 체력, 적 AI, 스폰, 경험치, 카드 적용, 재장전 | 실제 게임 규칙 변경      |
| `terrain.py` / `TileMap`                   | 맵 읽기·검증·확장·생성, 지형 충돌, 시야선, 경로 탐색          | 새로운 지형 효과·맵 규칙   |
| `renderer.py` / `Renderer`                 | 우주 그래픽, 카메라, 줌, HUD, 메뉴·카드 화면, 연출 캐시      | 색상·배치·카메라 표현 변경  |
| `progression.py` / `RewardCard`            | 5종 능력치·21종 전직·포신·무기 수치 정의                  | 카드 문구 변경         |
| `menus.py` / `MenuButton`                  | 버튼 ID·문구·영역·활성 여부                         | 버튼 추가·위치 변경      |
| `env.py` / `TankEnv`, `ObservationBuilder` | 코어를 학습용 인터페이스로 감싸고 관찰·보상·종료를 계산           | 학습 입력과 보상 변경     |
| `maps/*.txt`                               | 맵 템플릿 데이터                                 | 큰 벽·넓은 통로·시작 위치 배치   |
| `tests/`, `random_agent_test.py`           | 입력·규칙·메뉴·맵·재현성 검증                         | 변경 후 회귀 확인       |

PNG 로딩과 축소·회전 캐시는 `sprite_assets.py`의 `SpriteAssets`가 담당합니다. `assets/` 원본을 읽고 메모리에 변환 결과를 보관하며, 원본 PNG는 수정하지 않습니다. 창 크기·전체화면은 렌더러가 관리하므로 맵과 진행도에 영향을 주지 않습니다.

**`GameCore`와 `TileMap`은 Pygame을 가져오지 않습니다.** 화면 없이 게임을 실행할 수 있는 이유입니다. `Renderer`는 게임 상태를 읽어 그리며, 그림을 그리다가 체력이나 점수를 변경하지 않습니다. 다만 `set_zoom()`은 공유 설정의 카메라 배율을 바꿉니다.

## 실제 사용된 패턴에 가까운 것

거창한 패턴 이름보다 코드에서 확인할 수 있는 역할을 기준으로 적었습니다.

| 구조 | 코드에서 보이는 형태 | 의미 |
|---|---|---|
| 모델·뷰·컨트롤러 분리 | `GameCore` / `Renderer` / `GameApplication` | 규칙, 표시, 입력을 나눈 MVC와 유사한 구조. 완전한 MVC 프레임워크는 아님 |
| 어댑터 | `TankEnv`가 코어를 `reset()` / `step()` 인터페이스로 제공 | 같은 게임을 Gymnasium 방식으로 사용할 수 있게 변환 |
| 간단한 상태 머신 | `mode = main / playing / pause`, 별도 `game_over` | 설정 메뉴에서 시간을 멈추고 HUD 보상은 전투 중 선택. 정식 State 클래스 구조는 아님 |
| 생성자 주입 | `GameApplication(game, renderer)`, `GameCore(config)` | 필요한 객체·설정을 밖에서 전달. 테스트에서 화면을 대체하기 쉬움 |
| 데이터 중심 정의 | 설정 dataclass, `REWARD_CARDS`, `menu_buttons()` | 이름·설명·배치를 데이터로 모음. 카드 효과와 메뉴 동작은 아직 조건문에 있음 |
| 이벤트 누적 후 소비 | 코어의 `events` → `pop_events()` → `env.compute_reward()` | 게임에서 일어난 일과 학습 보상 계산을 분리. 콜백을 등록하는 Observer는 아님 |
| 생성 함수 | `_make_shape()`, `_make_terrain()`, `load_map()` | 엔티티·맵 생성 과정을 모음. 상속 기반 GoF Factory Method와는 구분 |
| 변경 버전 기반 캐시 | `TileMap.version`, 렌더러·관찰의 `(id, version)` 키 | 지형이 바뀌면 그림과 관찰 캐시를 갱신 |

현재는 ECS, 플러그인 방식 카드 효과, 상속 기반 직업 시스템을 사용하지 않습니다. `Tank`, `Shape`, `Bullet`은 데이터를 묶은 dataclass이고, 규칙은 코어의 메서드에서 처리합니다.

## 한 프레임이 지나가는 순서

사람 플레이에서는 입력 이벤트를 먼저 처리합니다. 이후 실제 지난 시간을 누적해 1/60초마다 코어를 진행하고, 마지막에 화면을 그립니다. 한 번의 화면 갱신에서 밀린 업데이트는 최대 5개까지만 처리합니다.

코어 안의 주요 순서는 다음과 같습니다.

1. 플레이어 이동과 마우스 조준.
2. 적 AI 또는 적의 재등장 타이머.
3. 플레이어 발사, 천체·탄환 이동.
4. 탄환 충돌, 몸체 충돌, 자동 회복.
5. 부족한 천체 보충.
6. 게임 프레임 증가, 재장전 완료 처리, 플레이어 사망 판정.

설정 메뉴에서는 컨트롤러가 코어를 호출하지 않아 재장전·회복·적 재등장·점사 시간이 멈춥니다. 일반 강화와 전직은 HUD에서 선택하며 전투가 계속됩니다. 별 반짝임 같은 화면 연출은 메뉴에서도 보일 수 있습니다.

## 책임 분리에서 주의할 부분

`GameCore`에는 전투, 성장, 적 AI가 함께 들어 있습니다. 지금 수정 위치는 찾기 쉽지만, 기능이 많아지면 이 파일이 가장 먼저 커집니다. 카드 정의와 실제 효과가 별도 파일에 있으므로 카드 효과를 바꾸면 문구도 함께 확인해야 합니다.

설정 객체는 여러 객체가 공유합니다. 줌처럼 표시만 바꾸는 설정은 즉시 변경할 수 있지만, 맵·지형 기능을 실행 중에 임의로 바꾸면 이미 생성된 타일과 설정이 달라질 수 있습니다. 해당 변경은 새 게임이나 맵 재생성까지 함께 고려해야 합니다.
